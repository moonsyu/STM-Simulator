# 결정 기록

## 2026-10-16 · Docs GPIO 함수 적용과 파일 진단

- 상황: LED의 WritePin 카드가 초기화용 RESET 호출만 미리 보기에 표시하고 실제 main 반복 영역을 비워 둠. 기존 검사는 함수/파일 추가 여부와 컴파일 중심이라 출력 동작을 놓침.
- 결정: GPIO 출력 함수의 명시적 main 예제를 제공하고 실제 LED 전류·점등을 검사. 미리 보기와 삽입의 동일 결과를 검증. 기존 사용자 코드와 정상 배선을 보존하고 누락 GND를 재연결.
- 진단: 사용자의 요청에 따라 실행 로그와 최근 자동 저장 회로 사본을 앱의 로컬 프로필에 보관. 외부 전송하지 않으며 로그 크기를 제한. 기존 버전은 화면 로그만 제공하므로 이번 진단은 Chromium Local Storage의 읽기 전용 사본을 사용.
- 범위: 기존 UI 구조 유지. 사용자 앱/회로는 직접 수정하지 않고 별도 테스트 회로에서 검증.

## 2026-10-17 · 전체 Docs 실행 감사

- 요청: 모든 장치의 Docs 코드 적용과 자동 배선을 실제 실행 로그로 검사.
- 방법: 114개 라이브러리 항목에 실제 신규 배치 기본값을 적용. 입력 변경, 출력 상태, 통신 응답, 표시 메모리, 기계 동작을 기록. 원본 예제와 main 삽입본 비교. 697개 단선 복구와 전체 누락/오접속 복구 후 재실행.
- 판정: 컴파일 성공과 HAL 호출 도달은 장치 기능 통과와 구분. 기존 예제 자체가 틀리면 그 예제와 토폴로지가 같아도 정상 판정하지 않음. Bare-metal은 HAL 실행기에서 실행 불가로 별도 표시.
- 범위: 테스트·보고서만 추가하고 생산 코드 및 사용자 프로필은 보존. 공개 0.23.1 EXE는 숨김 창과 별도 프로필에서 검사. 결함 위치는 보고서에 따로 저장.

## 2026-10-17 · Docs 감사 결함 수정과 0.23.2 재검증

- 승인: 발견한 문제 전체 수정, 실제 동작 로그로 재검사 후 버전·소스·Release 게시.
- main 삽입: 반환 임시 변수와 매개변수/지역 변수의 이름 공간을 분리하고 원본 식별자와도 충돌하지 않게 생성. 새 함수·파일은 추가하지 않음.
- 버튼: 4핀 예제의 내부 연결 접점을 2/3핀 변형에 합칠 때 기존 빵판 구멍의 연결을 모두 보존. 접점 키 중복으로 입력/접지가 사라지지 않게 연결을 보완.
- 인코더: main의 느린 폴링으로 2ms 에지를 놓치는 문제는 기존 TIM4 하드웨어 인코더 예제로 해결. main이 대기 중이어도 A/B 에지를 계수하며 콜백을 생성하지 않음. 독립 EXTI 예제는 유지.
- PWM: 커패시터 기준 예제에 PWM 모드를 명시하여 Docs 재생성에서도 PWM 초기화가 유지됨.
- 진단: 숫자 배열 32개 초과인 시뮬레이션 상태는 전체 값의 SHA-256·길이·0이 아닌 값의 수·앞뒤 표본으로 저장. 이벤트 크기 제한과 비상태 이벤트 검증은 유지. 8개 TFT를 함께 기록해 순서·스냅샷·전체 해시 검사.
- 검증: 동작·API 호출·배선 토폴로지·EXE 파일 로그를 구분. DHT/DS18B20은 변환 대기 때문에 5.5초, 나머지는 3.5초의 시뮬레이션 시간을 확보. 기존 0.23.1 실패 자료는 보존하고 새 버전 결과를 별도 저장.

## 2026-10-17 · 기존 HAL 예제 재검사와 코드 초기화

- 요청: 기존 HAL Docs도 확인·수정하고 코드 초기화 추가. 기존 화면의 도구 모음/확인창 형태를 유지하는 소규모 기능 추가로 처리하며 화면 재설계는 하지 않음.
- 검증 범위: Docs 매핑을 우회한 HAL 원본 40개를 독립 실행. 기존 장치·보드 Docs 36개와 카드 308개, 손상 배선 보완을 별도 실행. 기본 핀이 예약된 스테퍼/L298N도 검사하여 포트 재할당 결함 발견.
- GPIO 변환: 복합 비트 마스크는 목적 포트별 호출로 분리. 동적 마스크/상태 식은 지역 변수에 한 번 평가하고, 목적 마스크 0은 호출하지 않음. 기존 함수·파일을 추가하지 않으며 새 main 내부 블록으로 삽입.
- Docs 표시: 적용과 같은 GPIO·핸들 변환 사용, I²C 주소와 클록의 실제 초기화 값 반영. EXTI를 main 폴링으로 바꿀 때 최초 상태는 이벤트가 아니며 설정한 에지만 처리. PIR/엔코더의 원본과 Docs 방식 차이를 설명.
- 초기화: main만 기본 코드로 되돌리며 핀·회로·보조 파일 보존. 기존 Docs 바인딩을 지워 다음 적용에 과거 예제가 되살아나지 않게 함. main 중단점 정리, 취소/Esc/한 번의 undo, 실행 중 금지, 코드/회로 스냅샷 진단 포함. 자동 점멸·UART 메시지·PWM 시작을 초기화 코드에 넣지 않음.
- 배포: 0.23.3, Windows 전체 CI 후 동일 파일명 STM-Simulator.exe. 공개 파일 해시를 검증한 EXE에서 기존 Docs와 초기화/모터 로그를 다시 수집.
