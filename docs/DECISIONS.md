- Docs 표시: 적용과 같은 GPIO·핸들 변환 사용, I²C 주소와 클록의 실제 초기화 값 반영. EXTI를 main 폴링으로 바꿀 때 최초 상태는 이벤트가 아니며 설정한 에지만 처리. PIR/엔코더의 원본과 Docs 방식 차이를 설명.
- 초기화: main만 기본 코드로 되돌리며 핀·회로·보조 파일 보존. 기존 Docs 바인딩을 지워 다음 적용에 과거 예제가 되살아나지 않게 함. main 중단점 정리, 취소/Esc/한 번의 undo, 실행 중 금지, 코드/회로 스냅샷 진단 포함. 자동 점멸·UART 메시지·PWM 시작을 초기화 코드에 넣지 않음.
- 배포: 0.23.3, Windows 전체 CI 후 동일 파일명 STM-Simulator.exe. 공개 파일 해시를 검증한 EXE에서 기존 Docs와 초기화/모터 로그를 다시 수집.

## 2026-10-18 · 저장 보존과 프로젝트 전환 수정

- 프로젝트 파일 세트는 staged 파일과 복구 journal을 준비한 뒤 교체한다. 미완료 저장은 원래 세트로 복원하고, 외부 수정 내용과 충돌하면 덮어쓰지 않는다. 같은 폴더 저장은 직렬화한다.
- undo 묶음과 dirty 상태를 분리하고 저장 중 추가 편집은 미저장으로 유지한다. 정상 창 종료 전 최신 초안을 동기 기록한다. 초안 저장 실패로 종료가 취소되면 네이티브 도구를 먼저 종료하지 않는다.
- 프로젝트 전환 시 기존 터미널을 닫고 main/renderer의 폴더 문맥을 함께 변경한다. 새 폴더 열기/생성은 새 문맥을 보존하고 미저장 프로젝트/회로 파일은 이전 폴더 문맥을 제거한다.
- 실패/삭제 오류/프로세스 중단/복구 충돌/동시 저장 검사와 실제 Electron 저장·미저장 확인·터미널 cwd·즉시 종료 복원 검사가 통과했다.

## 2026-10-18 · C 실행·Docs·배포 감사 후속 수정

- C 표현식의 타입을 실행 값과 별도로 추적한다. sizeof는 식을 실행하지 않고, 사용자 구조체의 자연 정렬과 padding을 계산한다. unsigned 연산, float 포인터/중첩 필드, 재귀 초기화, octal/enum과 main 변환기를 독립 C/ARM 기대값으로 확인한다.
- Docs가 초기화 후 기존 보조 부품을 찾을 때 사용자 label을 식별자로 쓰지 않는다. GPIO 전기 네트·기능·pull·부품 조건과 다른 바인딩의 소유권 검사를 유지한다.
- Monaco의 내장 DOMPurify도 실제 번들에서 교체한다. npm 잠금 파일 갱신만으로 내장 사본까지 고쳤다고 판단하지 않는다. 원본 라이선스는 보존하고 빌드 그래프에서 구형 모듈이 제외되는지 확인한다.
- 기존 릴리스는 덮어쓰지 않는다. 새 릴리스 ZIP은 포터블 파일과 문서/메타데이터를 포함하고, 공개 다운로드·태그·성공한 CI 빌드·체크섬을 대조한다. 로컬 빌드에는 현재 commit과 미커밋 여부를 명시하고 CI 배포는 깨끗한 소스를 요구한다.
- 정상 경로 외에 저장 실패, 외부 편집 충돌, 즉시 종료, 라벨 변경 후 재적용 회귀를 유지한다. 임의의 모든 C 코드·다중 장치 조합·물리 보드 동작까지 검증했다는 의미는 아니다.
