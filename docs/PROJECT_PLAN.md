# 현재 작업 계획 — 0.23.8 상태 감사

작성일: 2026-10-18. 이 계획의 범위는 현재 제품의 분석이며 신규 구현 계획이 아니다.

- 목표: 저장·프로젝트 전환·HAL 실행·Docs 자동 배선·화면·실제 IDE 도구·배포에서 재현 가능한 문제를 찾고 후속 수정에 필요한 증거를 남긴다.
- 사용자: STM32 회로와 HAL 코드를 학습하는 Windows IDE 사용자.
- 제품 구성: Electron main의 파일/네이티브 도구/업데이트 처리, renderer의 편집기/회로/UI, bounded C/HAL 인터프리터, 장치/전기 모델, GitHub Windows 배포.
- 요구: 컴파일 성공만으로 판단하지 않고 실행 값과 파일·프로세스·진단 상태를 확인한다. 데이터 유실을 우선한다. 사용자 보고와 개발용 코드 위치를 분리한다.
- 범위: 현재 커밋과 공개 0.23.8, 저장 오류·급한 전환, 장치 114종, HAL 카드, C 의미 비교, 코드 초기화/재적용, Dark/White 화면, GCC/GDB/clangd/ARM 빌드, 공개 다운로드 무결성/실행, 의존성 권고.
- 제외: 제품 수정·버전 변경·배포, 사용자 회로 변경, 물리 STM32/ST-LINK 검증, 전체 C 표준 구현 또는 모든 입력 조합 보증.
- 제약: D 드라이브 현재 저장소만 사용한다. 독립 테스트 프로필을 사용한다. 사용자 diagnostics는 읽기만 하며 코드/로그를 저장소에 복사하지 않는다. 기존 릴리스나 태그를 수정하지 않는다.
- 위험: 성공 경로 검사 편향, 호스트와 Cortex-M4 ABI 차이, 경고를 실제 공격으로 과장, CI 결과와 공개 배포 파일 혼동. 독립 C/ARM 대조 및 공개 자산 직접 확인으로 구분한다.
- 단계: WBS PA-01 기준선 → PA-02 재현·검증 → PA-03 보고·개발 인계.
- 완료 기준: 확정 결함과 내부 잠재 경로·의존성 경고·검증 한계가 구분된 보고서, 별도 수정 위치, 재현 스크립트와 요약 증거. 실패를 발견한 검사가 실패 목록을 보존하면 감사 완료이며 제품 정상 판정은 아니다.

산출물: `docs/audits/2026-10-18-project/`. 새 UI나 아키텍처 변경을 구현하지 않으므로 UI 시안/설계 변경 승인은 이번 감사에 해당하지 않는다.
