# 구현할 기능 목록

구현해야 하는 기능을 적어 두고, 옆에 구현 상태를 적는다. 구현 계획은 기능마다 다른 파일에 쓰고, 그 위치를 **구현 계획** 칸에 적는다. 진행 기록과 검증은 [작업 로그](WORKLOG.md)에 둔다.

상태: `미착수` · `계획` · `진행 중` · `완료 (버전)` · `보류`

| 2 | FPB-RA6E1(Renesas) 보드 추가 | 완료 (1.25.0) | [docs/RA6E1-PLAN.md](RA6E1-PLAN.md) | 완료 (1.20.0): 1·2단계(FSP 설치·빌드, RA6E1 에뮬레이터, 보드·핀·그림). 완료 (1.22.0): 3단계 주변장치(SCI UART·GPT·AGT·ADC12·IIC), 4단계 Pins·Clocks·Stacks 설정과 예제 7개. 완료 (1.23.0): 5단계 FSP 정의 이동·자동완성, 6단계 앱 쪽(J-Link 기록·디버그). 완료 (1.25.0): 6단계 실물 확인(J-Link V9.92, 기록·검증·리셋, 디버그 중단점·호출 스택, 서브클록 미연결 반영) |
| 3 | CubeMX와 다른 점 메우기 | 진행 중 | [docs/CUBEMX-GAPS.md](CUBEMX-GAPS.md) | 완료 (1.21.0): ADC Continuous Conversion. 완료 (1.23.0): USART·SPI Parameter Settings. 완료 (1.24.0): TIM PWM 채널별 Pulse·극성·PWM mode, I2C1 주소·Duty·No Stretch. 완료 (1.26.0): 클록 트리(Clock 탭, ADC Prescaler 포함, [CLOCK-TREE-PLAN.md](CLOCK-TREE-PLAN.md)), ADC1 Sampling Time 선택. 남음: TIM Output Compare·Counter mode, TIM6/7·RTC·DAC 등(목록 순서) |
| 4 | CubeIDE의 printf 실수 출력 설정(Use float with printf from newlib-nano, `-u _printf_float`) | 완료 (1.25.0) | (계획 파일 없음, [HANDOFF](../HANDOFF.md) 1.25.0) | 구현: 프로젝트 `build.printfFloat`, IDE 툴바 printf float 칸(MCU/MPU Settings 대신 툴바), 두 ARM 빌드·해석기 적용, 꺼진 채 `%f`면 실행마다 출력 탭 안내 한 번, 실수를 찍는 예제는 켬. 조사 내용: 2026-11-06 실물 안내문 대조. 지금은 ARM GCC 빌드(시뮬레이터·실물 모두)가 `-u _printf_float`를 늘 넣고(`native-build.cjs` linkFlags), 해석기도 `%f`를 늘 출력한다. CubeIDE 새 프로젝트는 이 칸이 꺼져 있어 `printf("%.2f")`가 빈칸으로 나온다. 그래서 시뮬레이터에서 되던 코드가 실물에서 안 된다. 할 일: 프로젝트 설정(MCU/MPU Settings)에 CubeIDE와 같은 이름·기본값의 선택 칸을 두고 두 빌드와 해석기에 적용한다. 꺼진 채 `%f`를 쓰면 출력 탭에 한 번 안내한다 |
| 5 | STM32 핀 과전압 경고(3.3 V 초과 입력, 5 V 비허용 핀) | 완료 (1.25.0) | (계획 파일 없음, [HANDOFF](../HANDOFF.md) 1.25.0) | 구현: `src/pin-tolerance.js`, 문제 탭 오류·실행 중 출력 탭 한 번. 핀 구조 표는 데이터시트 원문 대조 전(WORKLOG). ADC 값은 그대로 0~3.3 V로 자른다. 조사 내용: 2026-11-06 실물 안내문 대조("입력 전압이 3.3 V를 넘으면 안 됨, 5 V에 연결하면 핀 손상"). 지금은 ADC 입력을 0~3.3 V로 조용히 자르고(`emu/stm32f446/adc.js` `convert`), GPIO·ADC 핀에 VDD를 넘는 전압이 걸려도 경고가 없다(Raspberry Pi 핀 안내에만 "3.3 V 전용"). 할 일: 핀 종류별 한계(FT 5 V 허용, TT·아날로그 핀은 VDD + 0.3 V)를 회로 해석 경고로 내고, 실행 중이면 출력 탭에 표시한다 |
| 6 | CubeIDE에서 생기는 인터럽트 핸들러 중복 정의 안내 | 완료 (1.25.0) | (계획 파일 없음, [HANDOFF](../HANDOFF.md) 1.25.0) | 구현: `src/irq-duplicates.js`, 문제 탭 경고(SysTick_Handler 포함, 생성기 형태·가져온 it.c 제외), 누르면 그 줄로 이동. 조사 내용: 2026-11-06 실물 안내문 대조("stm32f1xx_it.c에 ADC1_2_IRQHandler가 있으면 main.c의 것을 지움"). 앱은 main.c에 쓴 핸들러를 it.c에서 빼고 빌드한다(`build-environment.js`). 그래서 Pinout NVIC를 켠 채 main.c에 `ADC1_2_IRQHandler` 등을 써도 시뮬레이터에서는 되지만, CubeIDE 코드 생성 뒤에는 multiple definition 링크 오류가 난다. 할 일: NVIC가 켜진 인터럽트의 핸들러를 main.c에 직접 쓰면 문제 탭에 "CubeIDE에서는 it.c와 중복"이라고 알리고, HAL 콜백(`HAL_ADC_ConvCpltCallback` 등)을 쓰라고 안내한다 |
| 7 | 입력 중 자동완성에 HAL 함수가 빠지는 문제(`HAL_ADC_Start`·`Stop`·`Start_IT`·`Stop_IT`, `HAL_ADC_ConvCpltCallback` 등) | 완료 (1.25.0) | (계획 파일 없음, [HANDOFF](../HANDOFF.md) 1.25.0) | 구현: 비고의 할 일 세 가지, E2E `completion`(두 대상, Ctrl+Space 없이). 조사 내용: 2026-11-06 사용자 제보. SDK 색인에는 이 이름이 모두 있다(F103RB·F446RE 확인). 재현(1.24.1 코드, E2E): 대상 **실물 보드(ARM) + clangd 연결됨**에서 입력하는 동안 뜨는 목록이 비거나(`HAL_ADC_Conv` → 없음) 엉뚱한 항목만 나온다(`HAL_ADC_St` → `HAL_ADC_Start, Text`·`HAL_ADCEx_Calibration_Start`). Ctrl+Space를 누르면 바르게 나온다. 원인 두 가지: ① clangd 응답의 `isIncomplete`를 Monaco에 넘기지 않아(`code-editor.js` clangd 제공자가 `{suggestions}`만 반환) 처음 한두 글자에서 받은 결과(clangd 기본 100개 한도)만 걸러 쓴다. ② 문서 동기화가 500 ms 늦게 보내져(`native-ide-ui.js` `queueLanguage`) 입력 중 질의가 예전 내용으로 간다. 시뮬레이터 대상(clangd 없음)에서도 문제가 하나 있다: 지금 치고 있는 미완성 단어가 "프로젝트의 식별자"(Text) 항목으로 맨 위에 선택되어 Enter·Tab이 아무것도 채우지 않는다. 할 일: `incomplete` 전달, 질의 전에 최신 내용 동기화, 커서 위치의 단어를 식별자 후보에서 빼기. E2E로 입력 중 목록(Ctrl+Space 없이)을 두 대상에서 확인한다 |
| 8 | STM Studio에서 앱이 빌드한 ELF 읽기(디버그 정보 DWARF 4) | 완료 (1.25.0) | (계획 파일 없음, [HANDOFF](../HANDOFF.md) 1.25.0) | 구현: `-gdwarf-4`와 디버그 정보를 뺀 libgcc 사본, 툴체인 시험이 모든 컴파일 단위 버전 4 확인. STM Studio 자체로 읽어 보는 것은 하지 않았다(이 PC에 없음). 조사 내용: 2026-11-06 사용자 제보: STM Studio에 `native-builds/…/firmware.elf`를 넣으면 `GDB cmd [symbol-file …] failed: Dwarf Error: wrong version in compilation unit header (is 5, should be 2, 3, or 4)`. 원인: ARM GCC 15가 `-g3`만 주면 DWARF 5로 만들고(`desktop/native-build.cjs` flags), STM Studio 안의 오래된 GDB는 DWARF 2~4만 읽는다. 할 일: ARM 빌드(실물·시뮬레이터 ARM GCC·에뮬레이터)에 `-gdwarf-4`를 넣는다. 앱 쪽 영향 확인: 에뮬레이터 줄 정보(`src/emu/elf.js`)는 DWARF 2~5, 변수 그래프는 심볼 표를 쓰고, 앱 GDB(xPack 15)·clangd도 DWARF 4를 읽는다. 검증: 빌드한 ELF의 `.debug_info` 버전이 4인지, 에뮬레이터 중단점·변수 그래프·실물 디버그가 그대로인지 |
