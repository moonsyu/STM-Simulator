## 2026-10-28 · 1.9.0 ESP32 실물 빌드·업로드

- 요청: ESP32 실물 빌드·업로드를 앱에 넣을 것("넣어").
- 한 것과 이유:
  - 실행 대상에 연결된 ESP32 포트를 `ESP32 (COM4)`처럼 넣었다. STM32 실물 보드처럼 고르기만 하면 되게 하려고 USB-시리얼 칩(CP210x·CH340/CH9102·FTDI·ESP32 내장 USB)의 포트를 찾는다.
  - 빌드(Ctrl+Shift+B)는 Arduino IDE 2에 들어 있는 Arduino CLI로 ESP32 보드의 `sketch.ino`를 컴파일한다. 이 PC처럼 Arduino IDE를 쓰는 사람은 따로 설치할 것이 없고, IDE에 설치한 esp32 코어·라이브러리를 그대로 쓴다(IDE 설정 파일 사용). 오류는 문제 목록에 그 보드 파일의 줄로 나오고, 빠진 라이브러리와 코어는 이름과 설치 위치를 알려 준다.

## 2026-10-28 · 1.8.0 강의 예제 정리 · 강의 과제 · PWM LED 밝기 · 예제 분류

- 요청: 1) 라즈베리파이·ESP 예제 배선 최적화 2) 밝기 값에 따라 LED 밝기가 보이지 않음 3) 과제도 예제 코드로 4) 예제를 Raspberry Pi·STM·ESP로 분류 5) 두 종류 이상의 보드를 쓰는 예제는 모든 분류에 6) RPI-01·KER-01 같은 이해에 필요 없는 문구 제거.
- 한 일과 이유:
  - PWM LED 밝기: PWM을 평균 전압(예: 50% → 1.65 V)으로만 계산해서 빨간 LED 순방향 전압(1.8 V) 아래로 떨어져 꺼졌고, LED 그림도 켜짐/꺼짐 두 가지뿐이었다. PWM 핀에 듀티를 실어 LED 전류를 켜진 구간 전류 × 듀티로 계산하고(평균 전압은 모터·ADC용으로 유지), LED 렌즈·빛 번짐을 전류에 맞춰 흐리게 그린다. STM32 HAL PWM·`analogWrite`, ESP32 `ledcWrite`, 에뮬레이터, 라즈베리파이 예제에 모두 적용된다.
  - 배선: 라즈베리파이를 90° 돌려 빵판 왼쪽에 세웠다. 헤더 간격이 구멍 간격과 같아 핀이 빵판 줄과 나란해지고, 선이 핀 사이 틈으로 곧게 들어간다. 라즈베리파이 예제 15개 모두 선 교차 0(이전 KER-02 6곳, RPI-05 6곳), 선 길이는 KER-02 2583 → 848. ESP32는 비어 있는 a·j 구멍과 구멍 사이 틈만 쓰고 보드 위를 지나지 않게 했다. FW-09 교차 6 → 1, IOT-01 11 → 4(핀 순서상 남는 교차), FW-08 0. 30번 줄 LED가 ESP32 USB 커넥터에 가려 ESP32를 두 줄 올렸다.
  - 강의 과제: 이 PC의 강의 PDF(라즈베리파이와AI Day1~5, 리눅스커널프로그래밍 Day1~3)에서 회로가 있는 "도전" 8개를 예제로 만들었다(LED 3개 깜빡임, LED 제어 쉘, LED 밝기 쉘, 버튼 LED, 버튼 PWM 직접 구현, 크리스마스 트리, 커널 PWM LED, 커널 타이머 LED 2개). 답안 코드는 강의 코드가 아니라 앱 자체 작성. 쉘 과제를 위해 직렬 모니터에서 라즈베리파이로 줄 입력을 보낼 수 있게 했다. 출력만 하는 커널 과제·조사 과제·카메라/AI 과제·Sense HAT 과제는 회로가 아니라서 제외. 임베디드Firmware·AIoT 교재는 PC에 없어 그 과제는 넣지 못했다.
  - 분류와 이름: 예제 목록을 Raspberry Pi · STM32 · ESP32 묶음으로 보이고, 목록 위 단추로 한 묶음만 볼 수 있다. STM32·ESP32 I2C 통신은 두 묶음에 모두 나온다. 이름에서 강의 코드·라즈베리파이5·GPIO 목록을 빼고 "라즈베리파이 PWM LED"처럼 무엇을 하는지만 남겼다(코드로 검색은 가능).

## 2026-10-28 · 1.7.0 STM32 보드 여러 개

- 요청: STM32 보드도 회로에 여러 개 넣을 수 있게, 보드별 핀 설정·HAL 코드·실물 기록까지.
- 한 일과 이유:
  - NUCLEO-F446RE·F103RB를 다른 보드 목록에 추가. 보드마다 `main.c`·소스·Pinout 설정·중단점·장치 Docs 기록·ST-LINK를 저장한다(회로당 4개).
  - 편집할 보드를 고르면 그 보드와 주 보드의 소프트웨어·이름·자리를 맞바꾸고 배선 끝점 이름을 바꿔 적는 방식으로 구현했다. 회로는 전기적·시각적으로 그대로이고, 기존 Pinout·HAL 생성·빌드·GDB·실물 기록 코드를 고치지 않고 편집 중인 보드에 그대로 쓸 수 있기 때문이다. Undo로 되돌릴 수 있다.
  - 실행: 다른 보드는 자기 시점의 시뮬레이터 세션(또는 에뮬레이터 세션, 보드별 ELF 빌드)으로 같은 회로·시간축에서 돈다. 처음에는 공유 회로의 직전 결과만 보게 했더니 다른 보드의 SPI(CS를 내린 직후 전송)와 서보 PWM 폭이 틀렸다. 그래서 그 보드의 출력이 바뀌거나 시간 단계가 지날 때 모든 보드의 현재 출력으로 회로를 다시 풀도록 고쳤다(출력이 같으면 재사용). 다른 보드에 연결된 부품(OLED·서보·L298N과 모터 등)은 그 보드의 장치 모델 값으로 표시한다. L298N 뒤의 모터처럼 부품을 거쳐 연결된 경우도 신호선을 따라가 포함했다.
  - 보드 간 UART(시뮬레이터): TX와 같은 넷의 활성 RX, 같은 baud이면 바이트를 전달한다. 다른 보드 RESET·USER 버튼과 LD2도 동작한다.
  - 실물: 보드마다 ST-LINK를 먼저 정한 뒤(지정·보드 종류 일치·미확인 1개, 중복 금지) 보드별로 빌드해 차례로 기록·검증·리셋한다. GDB 디버그는 편집 중인 보드 하나에만 연결한다.
- 검증:

- 요청: LED 점멸 예제를 보드에 써서 동작 확인(기존 펌웨어 삭제 허락), 이어서 버튼으로 LED를 토글하는 예제를 빌드해 쓰고 확인.

- 버튼 토글: 보드 USER 버튼(B1, PC13) EXTI로 누를 때마다 LD2(PA5)를 전환하는 `exti` 예제를 같은 경로로 빌드했다(배선 불필요). ST-LINK가 복구되면 쓰고, PC13 EXTI 설정과 버튼을 눌렀을 때 ODR 변화를 확인한다.
- 사용자가 USB를 다시 꽂은 뒤 ST-LINK가 정상 연결됐다. `exti` 펌웨어 20.92 KB를 쓰고 검증·리셋했다.
- 실물 확인(SWD 핫플러그, 연결 횟수를 줄여 한 세션에 묶음): `SYSCFG_EXTICR4`가 EXTI13을 GPIOC로 연결(2), `EXTI_IMR`·`EXTI_FTSR` 13번 비트 1(하강 에지), NVIC `EXTI15_10`(IRQ40) 활성, PC13 대기 레벨 1(버튼 놓음). `EXTI_SWIER`로 EXTI13을 두 번 발생시켜 실제 인터럽트 처리기가 PA5(LD2)를 0→1→0으로 바꾸고 `EXTI_PR`을 지우는 것을 확인했다. `-w32`의 "Failed to download data"는 SWIER가 처리 후 스스로 0이 되어 쓰기 후 읽기 확인이 어긋난 것이며 쓰기는 적용됐다.
- 물리 버튼을 사람이 누르는 확인은 사용자에게 맡겼다(누를 때마다 LD2가 켜졌다 꺼짐).
