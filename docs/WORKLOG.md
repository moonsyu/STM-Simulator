## 2026-10-21 · 0.29.2 코드 정렬이 한 줄의 여러 문장을 나눔

- 요청: 코드 정렬이 들여쓰기(tab)만 고치고, `uint8_t bank[1]={1}, id[2]={0};if (…) {…;printf(…);} else printf(…);HAL_Delay(1000);` 같은 한 줄은 그대로다. 목표 형식은 문장마다 한 줄, `} else {` 중괄호, 연산자 공백은 그대로.
- 원인: 내장 정렬기(`formatC`)가 중단점·`USER CODE` 표식을 지키려고 줄 수를 바꾸지 않도록 만들어져 있었다.
- 수정: `formatCode`가 문장마다 줄을 나누고 들여쓰며, 중괄호 있는 갈래 뒤의 `else` 한 문장에 중괄호를 붙인다. 편집기는 원래 줄 단위로 바꿔 중단점이 문장을 따라가고, 저장 시 정렬은 중단점 줄을 다시 계산한다. 사용자가 준 목표와 글자 단위로 같은 결과를 단위 테스트와 실제 앱 E2E로 확인했다.
- 검증: `npm test` 680개 중 677 통과(실패 2개는 로컬 심볼릭 링크 권한), E2E 22개 중 21 통과·1 건너뜀. 테스트 창은 다크 모드·맨 뒤로 여는 임시 변경으로 돌리고 되돌렸다(스크립트: 세션 scratchpad `bgpatch.py`).
- 커밋: `9f5cc4b` 코드 정렬 기능, `28ee2e8` 0.29.2 버전.
- 첫 CI [39530166635](https://github.com/moonsyu/STM-Simulator/actions/runs/39530166635) 실패: `storage.e2e`에서 Ctrl+S 뒤 "파일 저장됨" 대기가 시간 초과됐다(로컬은 4/4 통과). 입력 직후 저장하면 마지막 입력이 예약한 자동 저장(200 ms 뒤)이 파일 저장과 겹쳐 상태를 "저장 중…/자동 저장됨"으로 덮어쓰는 경쟁 상태다(이번 변경과 무관한 기존 결함). 파일 저장 성공 시 대기 중인 자동 저장을 바로 기록하고 타이머를 취소하도록 고치고, 저장 0.5초 뒤에도 "파일 저장됨"인지 검사를 추가했다. Release·태그가 없으므로 같은 버전으로 다시 게시한다.
- 결과: [Release v0.29.2](https://github.com/moonsyu/STM-Simulator/releases/tag/v0.29.2), [CI 39531566516](https://github.com/moonsyu/STM-Simulator/actions/runs/39531566516) 성공. latest 지정, 태그·커밋 `292d402` 일치, 5자산과 EXE·ZIP 해시(ZIP 안 EXE 포함) 확인.

## 2026-10-21 · 0.29.1 `}` 자동 정렬 수정과 예제 코드 정리

- 요청: 중괄호 입력 시 자동 정렬이 동작하지 않는다, HAL 예제 코드가 한 줄로 몰려 있다, 테스트 창은 다크 모드로.
- 원인: `}` 정렬이 키 이름(`}`)으로 감지했는데 Windows 한글 IME에서는 키 이름이 `Process`로 온다. 기존 E2E는 `keyboard.type`으로 실제 `}` 키를 보내 통과했다. `keyboard.insertText('}')`로 IME 입력을 재현해 실패를 확인한 뒤, Monaco `onDidType`으로 바꿔 통과시켰다. 자동 닫힌 `}` 덮어쓰기도 함께 검사한다.
- 예제 정리: 54개 예제의 187줄에 여러 문장이 몰려 있었다. `expandC`로 한 줄에 한 문장씩 나누고 들여쓰기를 다시 계산한다. 127개 모두 토큰 불변·멱등을 단위 테스트로 확인했다.
- 테스트 창: 작업 중에는 다크 모드·비활성·맨 뒤로 여는 임시 변경을 쓰고 끝난 뒤 되돌렸다(커밋하지 않음). 메모리에도 기록했다.
- 검증: `npm test` 678개 중 675 통과(실패 2개는 로컬 심볼릭 링크 권한), E2E 21개 중 20 통과·1 건너뜀.
- 커밋: `6e53b25` `}` 정렬 IME 수정, `1728566` 예제 코드 정리, `3be9c02` 0.29.1 버전.
- 첫 CI [39527156197](https://github.com/moonsyu/STM-Simulator/actions/runs/39527156197) 실패: E2E에서 편집 메뉴의 "코드 정렬"에 단축키가 비어 있었다. 메뉴가 단축키·위치를 `toggle` 이벤트(메뉴가 이미 보인 뒤 비동기)에서 채워서 생긴 경쟁 상태다. 사용자에게도 잠깐 빈 단축키·이전 위치로 보일 수 있었다. `beforetoggle`에서 채우도록 고치고 로컬 E2E를 두 번 연속 통과했다. Release·태그는 만들어지지 않았으므로 같은 버전 0.29.1로 다시 게시한다.
- 결과: [Release v0.29.1](https://github.com/moonsyu/STM-Simulator/releases/tag/v0.29.1), [CI 39528002946](https://github.com/moonsyu/STM-Simulator/actions/runs/39528002946) 성공. latest 지정, 태그·커밋 `0173b64` 일치, 5자산과 EXE·ZIP 해시(ZIP 안 EXE 포함) 확인.
