# IDE와 시뮬레이터 사용법

STM Simulator 0.14.0은 프로젝트·코드·시뮬레이터·터미널을 한 화면에서 사용하는 학습용 IDE다.

## 패널 크기와 위치

- 패널 사이의 가로·세로 경계선을 끌어 크기를 조절한다. 코드 300px, 시뮬레이터 470px, 터미널 255px 같은 기존 고정 최소 크기는 적용하지 않는다. 분할 비율은 1~99%이며 완전히 숨기려면 제목줄의 접기 버튼을 사용한다.
- 제목줄을 다른 패널의 왼쪽·오른쪽·위·아래 가장자리로 끌어 놓는다. **이동** 메뉴로도 같은 배치를 선택할 수 있다. 터미널도 자유롭게 이동한다.
- 제목줄의 최대화 버튼이나 제목 더블클릭으로 해당 패널을 크게 보고, 다시 누르면 원래 배치로 돌아온다.
- 상단 **패널 표시**로 접은 패널을 복원하고 **배치 초기화**로 기본 IDE 배치를 복원한다.
- 경계선에 키보드 포커스를 두고 방향키로 2%, Shift+방향키로 10%, Home/End로 1%/99%까지 조절한다. 경계선 더블클릭은 균등 분할이다.
- 배치와 접힘 상태는 이 PC에 저장된다. 회로 파일의 배치나 다른 PC의 화면 크기와는 별개다. 작은 패널에서는 내부 도구 영역을 스크롤하거나 최대화할 수 있다.

## 프로젝트 생성과 파일 관리

**새 프로젝트**에서 이름, NUCLEO-F446RE 보드, 빈 HAL 또는 예제 템플릿, 저장할 상위 폴더를 선택한다. 폴더를 선택하지 않으면 미저장 프로젝트로 시작한다.

폴더 프로젝트는 다음 파일을 만든다.

```text
MyProject/
  stm-project.json     프로젝트 폴더 표시
  project.stm32lab      회로·핀 설정·소스 목록·디버그 설정
  main.c               주 소스
  main.h               초기 헤더
  user.c / user.h       사용자가 추가한 소스
```

**프로젝트 열기**는 이 형식의 폴더를 연다. **회로 파일 열기**는 기존 `.stm32lab` 단일 문서를 연다. CubeIDE의 기존 프로젝트는 코드 패널의 **Cube 프로젝트 폴더**로 가져온다.

왼쪽 소스 파일 목록과 상단 파일 탭에서 파일을 전환한다. **파일 추가**, **이름 변경**, **삭제**를 지원한다. main.c는 삭제하거나 이름을 바꿀 수 없다. 이름 변경 시 해당 파일을 참조하는 include를 갱신하며, 다른 소스에서 include 중인 파일은 삭제 전에 참조를 제거해야 한다. 보조 C/H 파일은 최대 40개다.

**파일 저장 / Ctrl+S**는 열린 프로젝트 폴더의 회로와 소스를 함께 저장한다. 새로 추가·이름 변경·삭제한 파일도 이때 반영된다. 저장 후 앱 밖에서 파일이 변경되었다면 덮어쓰기를 중단한다. 외부 변경을 확인하고 프로젝트를 다시 연다. 앱 재시작 시 자동 복구된 문서는 폴더 저장 연결을 복원하지 않으므로, 원래 폴더에 계속 저장하려면 **프로젝트 열기**를 사용한다.

## 코드 작성과 빌드

Monaco 편집기로 C/H 구문 색상, 줄 번호, 괄호 짝, 접기, 다중 커서, 파일별 커서 위치를 제공한다. Ctrl+Space는 프로젝트 식별자와 주요 지원 API를 제안한다. 알려진 API는 마우스를 올리면 호출 형식을 보여준다. F12는 프로젝트 소스에서 찾을 수 있는 함수 정의로 이동한다.

Ctrl+F는 현재 파일 찾기, Ctrl+R은 바꾸기, Ctrl+Z/Y는 프로젝트 실행 취소/재실행이다. 코드와 회로 변경은 같은 프로젝트 이력에 저장된다.

**빌드 / Ctrl+Shift+B**는 지원 C/H 문법과 전처리를 검사하고 시뮬레이터 실행 프로그램을 준비한다. 빌드 오류를 누르면 원래 C/H 파일의 해당 줄로 이동한다. 배선·전원·HAL 설정은 실행할 때 추가로 검사한다.

이 빌드는 ARM GCC의 네이티브 빌드가 아니다. ELF/BIN을 만들거나 전체 ST HAL 드라이버를 컴파일하지 않는다. 자동 완성과 함수 찾기는 식별자·지원 API·함수 형태를 이용한 기본 기능이며 clangd의 완전한 C 의미 분석은 포함하지 않는다. 별도 개발자 검증 명령 `npm run test:main-c`와 앱의 빌드는 서로 다르다.

## 실행과 소스 디버그

| 조작 | 동작 |
|---|---|
| F5 / 실행 | 시작, 실행 중 정지, 중단점에서 계속 실행 |
| 디버그 시작 | 첫 실행 문장 앞에서 멈춤 |
| F9 / 줄 왼쪽 표시 영역 클릭 | 현재 파일·줄의 중단점 추가/제거 |
| F6 | 다음 실행 문장에서 일시정지 |
| F10 | 현재 문장 실행, 호출 함수는 끝까지 실행 |
| F11 | 함수 안으로 한 단계 실행 |
| Shift+F11 | 현재 함수 밖으로 실행 |
| Shift+F5 / 정지 | 실행 종료 |
| 기존 ‘한 단계’ | 시뮬레이션 시간 20ms 진행; 소스 한 줄 실행과 별개 |

멈춘 줄은 코드에서 강조된다. 터미널의 **디버그** 탭에 현재 함수의 지역 변수, 프로그램 전역 변수, 호출 스택, 중단점, 감시식을 표시한다. 스택 항목을 누르면 해당 코드로 이동한다. 감시식은 `counter`, `values[0]`, `counter+1` 같은 읽기 전용 식이며 함수 호출·대입·증감은 허용하지 않는다.

중단점과 감시식은 프로젝트에 저장한다. 편집기에서 줄을 삽입·삭제하면 중단점 위치도 이동한다. 주석·선언 전용 줄에는 실행 문장이 없어서 멈추지 않을 수 있다. 실행 중에는 소스 변경이 잠긴다.

현재 디버거는 시뮬레이터의 C 소스 실행기다. CPU 레지스터·메모리 주소·GDB·ST-LINK·실제 ARM 펌웨어 실행은 지원하지 않는다. 인터럽트·주변장치 콜백은 한 번에 처리하므로 콜백 내부 중단점과 한 줄 실행은 지원하지 않는다. 회로·시간 모델의 범위는 [HAL API](HAL-API.md)를 따른다.
