# 장치 Docs와 예제 적용

회로에서 부품·STM 보드·빵판을 선택한 뒤 코드 패널의 **장치 Docs** 탭을 엽니다. 다른 장치를 선택하면 문서도 바뀝니다.

## 장치와 예제 찾기

조사한 80개 항목은 보드·빵판 2개와 물리 부품 변형 78개입니다. 기존 학습 부품 35종을 보존하여 추가 메뉴에는 **114개 항목** (보드 1개 포함), HAL 예제에는 **120개**가 있습니다. 이 수치는 서로 다른 기기 120종을 뜻하지 않습니다.

- **HAL 예제 검색**: 장치명, 핀 수, 인터페이스, HAL 함수로 검색합니다. 예: `부저 3핀`, `OLED SPI`, `HAL_I2C_Mem_Read`.
- 예제 선택은 회로·코드·핀 설정을 함께 교체합니다. 현재 작업에 추가하려면 장치 Docs의 적용 버튼을 사용합니다.
- Docs에는 개요, 출처, 물리 접점과 배선표, HAL 함수 설명·호출 예제, Bare-metal 레지스터 예제가 있습니다.
- [80개 모형 갤러리](device-model-gallery.html), [참고 사진 갤러리](device-reference-gallery.html), [항목별 지원 범위](DEVICE-CATALOG.md)를 함께 제공합니다.

## main.c에 직접 삽입

0.23.3부터 적용 후 미리보기는 실제 배정된 GPIO·타이머·I²C 주소와 현재 클록의 초기화 값을 표시합니다. 여러 GPIO를 한 번에 쓰는 비트 마스크와 스테퍼의 동적 위상 마스크도 재배선된 포트에 맞게 변환합니다. 기존 핀을 다른 부품이 사용해 서로 다른 포트에 배치되는 경우에도 모든 대상 핀을 갱신합니다.

PIR Docs는 main에서 입력 변화를 폴링하며 시작 상태를 이벤트로 오인하지 않습니다. 원본 HAL 예제 목록의 PIR·USER 버튼·엔코더 인터럽트 예제는 유지합니다. 엔코더 장치 Docs는 TIM4 하드웨어 카운터를 사용합니다.

**HAL 예제 + 핀·배선 보완**은 장치 예제를 현재 코드에 추가합니다. 함수별 **main에 코드 적용**은 선택한 호출과 필요한 준비 코드·버퍼를 삽입합니다. Docs의 코드 창에는 main 안에 작성할 문장만 표시합니다.

새 함수나 파일은 만들지 않습니다. 예를 들어 `HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_RESET);`을 main의 실행 루프에 넣고, 해당 핀 설정은 기존 `MX_GPIO_Init`에 추가합니다. 주변 장치 초기화 함수가 이미 있으면 그 함수 안에 설정을 보완하며, 없으면 초기화 본문을 main에 직접 넣습니다. 필요한 HAL 핸들 선언은 main.c의 전역 선언부에 추가합니다. LCD·센서의 보조 함수도 호출 지점의 C 블록으로 펼칩니다.

변수 선언은 main 시작, 일회성 동작은 `USER CODE BEGIN 2`, 반복 동작은 `USER CODE BEGIN 3`에 들어갑니다. 표식이 없으면 main과 중괄호로 된 무한 루프를 찾아 삽입합니다. 기존 사용자 코드와 초기화 함수는 유지합니다. UART·EXTI Docs 예제는 새 콜백 함수가 필요 없도록 main에서 폴링합니다. 독립 HAL 예제 메뉴의 인터럽트 예제는 그대로 제공합니다.

`STM DEVICE DOCS` 표식과 체크섬으로 관리하는 영역은 재적용 시 교체하며, 사용자가 편집한 영역은 덮어쓰지 않습니다. 이전 버전의 생성 파일·보조 함수 영역·콜백 연결 코드는 검증 후 정리합니다. 사용자 콜백의 나머지 문장은 보존합니다. 기본 생성기의 빈 루프에 있던 `HAL_Delay(500)`만 제거하며 사용자가 작성한 대기 코드는 유지합니다.

여러 장치의 반복 코드는 순서대로 실행합니다. 각 예제와 사용자 코드의 `HAL_Delay`는 전체 응답 주기에 영향을 줍니다.

인코더와 KY-040의 Docs 예제는 TIM4의 A/B 하드웨어 계수 기능을 사용합니다. main이 대기하는 동안에도 에지를 세며, TIM4를 이미 사용 중이면 가능한 다른 인코더 타이머와 핀으로 배정합니다. 독립 HAL 메뉴의 EXTI 인코더 예제는 그대로 제공합니다.

## 핀 활성화와 배선 보완

LED의 `HAL_GPIO_WritePin` 단독 카드는 `HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);`을 main 실행 영역에 넣습니다. 사용 중인 PA5를 다른 핀으로 배정하면 해당 호출도 바뀝니다. GPIO 초기화의 RESET 호출은 초기 출력값 설정이며 점등 예제를 대신하지 않습니다. SET을 RESET으로 바꾸면 소등됩니다. 전체 LED 예제의 TogglePin 깜빡임 동작은 유지합니다.

보드가 없으면 NUCLEO-F446RE 한 개를 추가합니다. 선택 부품의 위치·회전·크기·환경 설정을 유지하고 필요한 저항·전원·드라이버를 추가합니다. 사용할 수 있는 GPIO·주변장치를 활성화하고 정상 연결을 재사용하며, 누락된 연결과 잘못된 전원/GPIO 연결을 보완합니다. 보존된 선의 꺾임점도 유지합니다.

다른 장치의 핀 점유, 공유 버스 설정, 주소 충돌을 검사합니다. 가능한 경우 다른 타이머·UART로 배정합니다. 고정 타이밍이나 비트 마스크가 포함된 예제는 해당 핀과 클록을 요구합니다. 빵판 내부 버스 자체가 두 신호를 합치는 등 자동 보완할 수 없는 경우 적용을 취소하고 원인을 표시합니다. **Ctrl+Z**로 코드·핀·부품·배선을 함께 되돌립니다.

## 배선 이어 그리기

시작 핀 → 빈 바닥의 꺾임점 → 다음 꺾임점 → 끝 핀 순서로 클릭합니다. **Backspace**는 마지막 꺾임점, **Esc** 또는 **우클릭**은 진행 중 배선을 취소합니다. 배선 색은 기본색 10개와 파스텔 10개로 총 20개입니다. 끝 핀을 선택하기 전에는 전기 연결을 만들지 않습니다. 이미 완성된 선은 더블클릭으로 점 추가, 드래그로 이동, 우클릭으로 점 삭제가 가능합니다. 부품이나 완성된 선을 선택한 상태의 Esc 삭제 기능은 유지합니다.

## Bare-metal 범위

레지스터 예제의 GPIO·ADC·TIM·UART·SPI·I2C 초기화, 시간 대기와 동작은 CMSIS 레지스터 접근으로 생성합니다. 기존 프로젝트의 `HAL_Init` 및 시스템 클록 설정은 유지하므로 프로젝트 전체가 HAL 없는 펌웨어로 바뀌는 것은 아닙니다. SPI는 송수신, I2C는 주소 ACK 검사와 현재 포인터의 1바이트 수신 예제를 제공합니다. 이 항목들은 모든 장치의 프로토콜 전체를 구현한 레지스터 드라이버는 아닙니다.

직접 레지스터 접근은 ARM 빌드 대상으로 전환합니다. 회로의 HAL 인터프리터는 직접 레지스터 코드를 실행하지 않습니다.

## 회로 실행과 ARM 빌드의 구분

80개 조사 항목 모두 외형·접점·배선·HAL 예제·Docs·코드 삽입과 **기본 예제의 회로 실행**을 지원합니다. 모든 기능을 구현한 실제 칩 에뮬레이션을 뜻하지는 않습니다.

- DS18B20: 실제 GPIO 에지 기반 1-Wire 리셋, Skip ROM, 750 ms 변환, 스크래치패드와 CRC. 단일 센서/외부 전원 모델입니다.
- DHT11/22: 시작 신호, 40비트 데이터와 체크섬. 설정한 온습도와 단선·전원 실패가 응답에 반영됩니다.
- URM09 Trig: 단일 GPIO의 입력/출력 전환과 거리 비례 Echo 폭.
- CAN: 기본 예제는 `CAN_MODE_LOOPBACK`으로 표준 ID·32비트 필터·FIFO 송수신을 검사합니다. `CAN_MODE_NORMAL`에서는 외부 상대 노드가 없어 ACK 오류 32가 발생합니다. 외부 CAN 버스의 중재·다중 노드는 구현하지 않았습니다.
- MAX98357A: I2S2 16 kHz·16비트 PCM 수신, SD 채널 선택/정지와 주파수·프레임 표시. 소리 버튼은 측정 주파수의 시험음이며 실제 PCM 음악 출력과 스피커 전력 모델은 아닙니다.
- OV2640: XCLK·리셋·SCCB 식별값 읽기까지입니다. DCMI 영상 캡처는 포함하지 않습니다.
- SD: SPI 초기화·OCR 확인까지입니다. 블록 데이터 및 파일시스템 읽기/쓰기는 포함하지 않습니다.

원본 HAL 예제와 `main.c`에 삽입한 결과를 실제 STM32 HAL/CMSIS로 컴파일·링크합니다. 이것은 실물 보드 실행 검사나 ARM CPU 명령 실행이 아닙니다. 현재 검증 증거는 [VERIFICATION.md](VERIFICATION.md)에 기록합니다.

참고: [ST HAL 헤더](https://github.com/STMicroelectronics/stm32f4xx-hal-driver/tree/master/Inc), [STM32F446 CMSIS 정의](https://github.com/STMicroelectronics/cmsis-device-f4/blob/master/Include/stm32f446xx.h). ST SDK는 사용자 개발 도구 경로에서 사용합니다.
