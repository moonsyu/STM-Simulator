# 작업 화면 개선 구현 기록

2026-10-19. UI-01~06 소유 변경 및 실제 검수 기록입니다. 코드 위치는 내부 수정 추적용이며 사용자 요약에서는 생략합니다.

## 적용 내용

- `src/workbench-ui.js`: 기존 컨트롤 DOM을 재사용해 프로젝트/코드 도구/배선 색상/실행 보조 도구/실행 상태 메뉴로 묶었습니다. 보조 프로젝트 파일·HAL 예제·보드 핀 설정은 이름이 있는 summary에서 펼치는 top-layer popover로 접근합니다. 부품 목록의 높이를 빼앗지 않고 원래 ID/리스너/입력값을 유지합니다. Escape는 열린 메뉴를 닫으며 회로 선택 삭제로 전파하지 않습니다.
- `src/preferences.css`: UI 글꼴 크기 설정을 실제 컨트롤과 설명에 적용했습니다. 보조 글자도 11px 미만으로 내려가지 않습니다. Monaco, 코드 샘플, 터미널 출력, 장치 SVG는 독립된 폰트 설정을 유지합니다. 배선 팔레트 클릭 영역을 24×24px로 키웠습니다. Pinout 핀 타일은 큰 글자에서 이름/용도가 겹치지 않도록 내용에 맞는 최소 높이를 가집니다. 새 외부 핀 라벨은 테마 전경색과 배경 테두리를 사용합니다.
- `src/ide.css`: 저장 상태를 모든 폭에서 표시하고 상단 요소가 겹치지 않게 유연한 높이를 사용합니다. 좌측 전체 패널 스크롤을 없애고 부품 목록만 스크롤합니다. 긴 부품 이름·설명은 툴팁을 유지하며 두 줄로 제한합니다. 코드 제목/탭의 중복 행을 합치고 clangd를 코드 도구 메뉴로 옮겼습니다. 파일 선택기는 항상 드러납니다.
- `src/workspace-layout.js`: 사용자가 손대지 않은 기본 배치에서만 좁은 창의 부품 목록 폭과 로그 두 줄을 위한 터미널 높이를 계산합니다. 수동 크기 조절/도킹 후에는 자동 조정을 끄고 저장된 사용자 비율을 유지합니다. 최소 드래그 제한은 추가하지 않았습니다.

## 실제 확인과 후속 수정

첫 probe는 900×560/11px에서 정상 측정을 얻은 뒤 다음 스크린샷 캡처가 지연되었습니다. `showInactive()`를 포함한 별도 프로필 재검사에서는 21개 화면을 모두 캡처했습니다. 결과는 `work/tinkercad-ui-round1/metrics.json`, `probe-round2.log`, 같은 폴더의 PNG에 있습니다.

- 폭/높이: 900×560, 1024×640, 1366×768, 1540×900.
- 글꼴: 코드 화면 11/13/20px, 설정·Pinout 20px, 팔레트 20px.
- 21개 상태 모두 page error 0, HTML 텍스트 대비 실패 0, 표시 글자 11px 미만 0.
- UI 컨트롤은 11/13/20px로 실제 변했으며 Monaco 코드는 14px를 유지했습니다.
- 저장 상태/프로젝트 이름 상단 겹침과 문서 가로 넘침은 재현되지 않았습니다.
- 큰 글자에서 Pinout 타일 내용이 눌리는 현상과 작은 창에서 로그 높이가 부족한 현상을 추가 발견했습니다. 타일 최소 높이를 수정하고 실행 상태의 보조 행·중복 코드 헤더를 정리했습니다.

마지막 헤더/상태 메뉴 변경 후의 전체 24조합·키보드·기능 회귀 검사는 병렬 검증 작업이 이어서 실행합니다. 위 21개 측정만으로 마지막 변경의 완료를 단정하지 않습니다.

후속 실제 화면 검수에서 코드 8줄과 로그 2줄은 확보했지만, 900×560/20px 모니터 탭이 실행 상태 버튼을 침범하고 Pinout 다음 행이 위 행의 설명을 덮는 현상이 확인되었습니다. 전자는 탭 컨테이너만 축소·스크롤하도록 분리하고 실행 상태/지우기 버튼의 폭을 보존했습니다. 후자는 타일 최소 높이뿐 아니라 그리드의 암시적 행 높이도 동일한 내용 기준으로 지정했습니다. 이 두 항목은 요소 경계 검사와 다음 실제 화면으로 다시 검증합니다.

## 실제 UI 접근 경로

| 컨트롤 | 열기 경로 |
|---|---|
| 새 프로젝트/프로젝트 열기/회로 열기/배치/업데이트 | `#project-actions-toggle` |
| 프로젝트 파일 작업 | `#project-library-tools > summary` |
| HAL 예제 검색/적용 | `#hal-library-tools > summary` |
| 보드 선택/Pinout/보드 초기화/핀 검색 | `#board-library-tools > summary` |
| 코드 가져오기/검사/초기화/실행 환경/clangd | `#code-tools-menu-toggle` |
| 배선 색상 20개 | `#wire-color-menu-toggle` |

## 키보드와 도킹 충돌 보완

정적 검토에서 부모 헤더가 `draggable`일 때 `dragstart.target`만 검사하면 자식 탭에서 시작한 포인터 드래그를 구분하지 못할 수 있음을 확인했습니다. 실제 `pointerdown`의 시작 위치가 탭/버튼이면 도킹을 차단하고, 탭의 ContextMenu/Shift+F10을 도킹 이동 명령으로 해석하지 않도록 분리했습니다. 탭 방향키의 기존 `stopPropagation()`과 도킹 grip 방향키 동작은 유지됩니다.

메뉴 버튼은 native `popovertarget` 관계를 사용합니다. 키보드로 메뉴를 열면 첫 활성 컨트롤로 진입하며, 패널을 닫은 뒤 숨은 컨트롤에 포커스가 남으면 opener로 복원합니다. 별도 대화상자를 여는 동작은 그 대화상자 포커스를 유지합니다. 이 보완은 JS 문법 검사와 diff 검사를 통과했으며 실제 키보드 검사는 다음 앱 시작의 회귀 검사에서 확인합니다.

Round 3 실행에서는 Pinout 내용 경계와 모니터 버튼 겹침 검사가 통과했지만 900×560/20px의 마지막 모니터 탭 포커스 노출이 두 테마에서 실패했습니다. 이후 탭의 실제 경계와 tablist의 `clientWidth`를 비교해 필요한 만큼 해당 tablist의 `scrollLeft`만 이동하도록 보완했습니다. 키보드로 상태를 바꾸는 동안 글자 폭이 변하는 경우는 다음 프레임에 한 번 더 확인합니다. 이 스크롤 수정과 위 메뉴/도킹 키보드 보완 3건은 Round 3 앱 시작 이후 변경되어 별도 새 프로세스 확인이 필요합니다.
