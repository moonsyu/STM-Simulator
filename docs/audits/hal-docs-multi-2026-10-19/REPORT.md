# HAL Docs 여러 예제 적용 검사

검사일: 2026-10-19. 대상은 `D:\codex\project\STM-Simulator`의 0.25.0 개발 소스 수정본이다. 이전 PIN 검사에서 수정한 내용은 유지하며, 이번 작업은 제품 코드를 변경하지 않는 동작 검사다. 공개 Release EXE 검사와 구분한다.

상태: **검사 완료. 실제 UI 3/3 시나리오, 독립 소스 실행 7/7 시나리오 통과.** 서로 다른 장치 예제는 함께 적용·실행되며, 같은 장치의 여러 카드를 독립적으로 누적하는 기능은 없다.

## 확인된 적용 방식

- **서로 다른 장치:** 각각의 Docs 적용을 현재 `main.c`에 함께 합성한다. 기존 사용자 코드와 다른 장치의 예제를 보존하고 필요한 핀·주변장치와 배선을 추가한다.
- **같은 장치의 함수 카드:** 장치 하나에 선택 API 하나를 저장한다. 다른 카드를 누르면 그 장치의 이전 선택을 교체한다. 원하는 함수 카드를 여러 개 독립적으로 누적하는 기능은 현재 없다. 선택 함수에 필요한 앞부분 준비 코드가 같이 들어가는 것은 카드 다중 선택과 다르다.
- **전체 예제:** `HAL 예제 + 핀·배선 보완` 버튼은 해당 장치의 전체 예제를 적용한다. 함수 카드 한 장을 고른 것과 구분한다.
- **실행 순서:** 여러 장치 코드가 main 루프 안에서 순서대로 실행된다. `HAL_Delay`나 대기형 통신은 다음 장치 처리와 폴링 응답을 늦출 수 있다. 여러 장치가 한 프로젝트에서 동작한다는 것이 독립 병렬 작업 실행을 뜻하지 않는다.
- **자원 충돌:** 가능한 다른 GPIO·타이머·UART를 배정하고, 호환되는 I²C 버스는 공유한다. 중복 I²C 주소나 UART 자원 소진 등 해결할 수 없는 경우 적용을 거부한다.

## 실제 검사 범위

1. 같은 LED에서 WritePin → TogglePin → ReadPin → WritePin 카드 적용 및 재적용. ReadPin 카드에 포함된 앞선 Toggle 동작은 준비 코드이며, 다중 카드 선택 결과로 판단하지 않았다.
2. LED 2개를 서로 다른 핀에 적용해 함께 실행.
3. LED + 가변저항 + UART + 서보를 차례로 적용하고 기존 코드·설정·배선 보존, 재적용·저장 복구·실행 확인.
4. 서보 2개의 타이머 분리와 각도 변화.
5. I²C 센서 2개의 주소 분리·버스 공유와 각각의 온습도 응답.
6. UART 2개의 주변장치·baud·송수신 분리.
7. 중복 I²C 주소·7번째 UART·직접 편집한 Docs 관리 영역의 거부와 기존 프로젝트 보존.

실제 UI 경로와 독립 `SimulationSession` 경로는 결과에서 따로 집계한다. 114개 장치의 모든 임의 조합, 실제 STM32 보드, ARM 펌웨어, 병렬 스케줄링을 검사했다는 의미는 아니다. 사용자 프로필·회로는 사용하지 않는다.
