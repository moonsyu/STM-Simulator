# PIN 옵션 검사 작업 로그

## 착수 — 2026-10-19

- 기존 기록을 확인한 결과, HAL 적용 검사는 있었으나 EXTI 에지·초기 출력·NVIC 우선순위를 실제 설정 UI에서 변경하는 교차 검사가 빠져 있었다.
- 기존 MCU 기본값 요약 JSON은 0.24.0 결과이고 최신 0.25.0의 성공 근거는 보관된 CI4 로그임을 구분했다. 이전 파일은 덮어쓰지 않는다.
- UI 검사, 설정 편집 감사, HAL 실행 감사로 분담했다. 앱 실행은 독립 프로필 한 개씩 순차 수행한다.

## 초기 결함

- `pinout-ui.js`: 타이머 모드 변경 시 현재 핀 편집 동기화가 빠져 입력 중 라벨이 사라진다.
- 숫자 필드의 빈 문자열이 `Number('')`에 의해 0으로 저장될 수 있다. priority/ARR 등의 0은 의미 있는 값이므로 빈 입력과 구분해야 한다.
- 핀 용도 변경 실패 시 변경 전 snapshot이 현재 라벨 입력보다 앞선 상태라 입력 중 라벨도 취소된다.
- HAL 실행 감사 277조건 중 274개 통과, 3개 실패: 첫 IRQ 콜백에서 다른 IRQ 차단, 전체 IRQ 차단, 후속 IRQ 우선순위 변경이 이미 추출된 ready 배치에 반영되지 않는다. 최초 재현은 `work/pin-runtime-audit/`에 보존한다.
- 수정 및 실제 UI 재검사는 진행 중이다. 위 초기 결과를 완료 판정으로 사용하지 않는다.

## 수정 후 중간 검사

- 라벨 소실 2경로와 숫자 입력 검증을 수정했다. 실제 UI 최초 재검사 7/7 통과: `work/test-results/pin-options-0.25.0-after-validation/summary.json`. 이 결과는 전체 행렬 완료가 아니다.
- IRQ 처리 수정 후 전체 단위 검사 401/401 통과: `work/test-results/pin-options-unit-2026-10-19.log`. 독립 생성 HAL/SimulationSession 검사는 277/277 통과: `work/pin-runtime-audit/results-after.json`.
- 후속 검토에서 잘못된 PWM CCR을 입력한 뒤 모드를 바꾸면 오류 입력란이 숨는 문제가 발견됐다. 실제 UI 실패 증거를 먼저 남긴 뒤 전환 차단과 입력 보존을 추가한다.
- 검사 자체의 오탐을 막기 위해 요청한 NVIC 우선순위와 저장값을 직접 비교하도록 보강한다. 저장값과 생성 코드끼리의 비교만으로 통과 처리하지 않는다.
- CHANGE 에지 계측의 연속 `printf`가 진단 대기열 64건 한도에 닿은 probe는 실패 기록으로 보존한다. 계측 출력을 단계별로 묶고 고유 실행 표식/회로 해시로 로그를 구분한다. 진단 대기열의 기존 용량 제한을 제거했다고 주장하지 않는다.
- 이전 0.24.0 MCU JSON SHA-256: `c60c13fea7e3f66beec148b7b4f7b233ab25e9ab366a5f47d403a37ab1bdad9f`. 기존 파일은 변경하지 않는다.
- 재실행 명령 `npm run test:pin-options:ui`를 추가했다. Windows CI에는 설정 검증과 동적 IRQ 콜백 회귀 범위를 추가하고, 버전별 PIN/MCU 검사 폴더의 실패 로그 수집 경로도 등록했다. 이번 작업에서 원격 CI를 실행했다는 뜻은 아니다.

## 독립 검토로 추가 발견한 Analog 결함

- 초기 UI 계측은 기존 구현처럼 Analog를 일반 Input/Pull로 읽는 값을 기대했다. 이 오라클을 정답으로 채택하지 않고 공식 명세와 대조했다.
- ST RM0390 Rev9 §7.3.12, p.182/1321은 Analog에서 내부 약한 pull-up/pull-down과 디지털 입력 버퍼가 비활성화되고 IDR 읽기는 0임을 명시한다. [ST 원본](https://www.st.com/resource/en/reference_manual/dm00135183.pdf).
- 현재 HAL 모델의 Analog/ADC1 설정이 `INPUT_PULLUP/PULLDOWN`으로 연결되고 디지털 읽기도 외부 전압을 반환하는 차이를 확인했다. 설정 UI 및 생성 PUPDR 값은 보존하되 실효 내부 Pull·디지털 읽기와 ADC 전압 측정을 구분하는 수정/검사가 필요하다.
- `pin-options-0.25.0-full-run1`은 validation19와 용도370선택 후 첫 GPIO 검사 도중 계획적으로 종료했다. 해당 폴더의 `interruption.json`과 실패/중단 summary는 보존한다. 전체 성공 근거로 사용하지 않는다.
- 순수 SimulationSession 277판정에는 EXTI0/1 우선순위16×16, mask/resume, 동적 우선순위, 에지, 입출력 논리 읽기가 포함된다. 그 중 Pull 전압은 기록만 했으므로 전압 판정까지 통과했다는 의미가 아니다. 실제 UI 전압 검사를 별도로 수행한다.

## 최종 수정·재검사 완료 — 2026-10-19

- Analog 전용 런타임 모드를 적용해 내부 Pull과 디지털 읽기를 차단했다. ADC와 외부 전압 측정은 유지하고 Input/DeInit 전환으로 디지털 입력이 복구되는지도 확인했다. 최종 전체 단위 검사 **406/406**, 실패·skip 0이다.
- 독립 HAL/SimulationSession 감사 **277/277**, Analog 사전 UI 검사 **11/11**, MCU 기본값 실제 UI 설정·생성·실행·저장 복구가 통과했다. MCU TIM3의 PSC=15/ARR=999/CCR=250에서 PA6 평균 출력 0.825V, fault=false를 실제 진단 로그로 확인했다.
- 최종 전체 UI 실행: KST 17:08:41–17:25:02, **362/362 통과**, 종료 코드 0. validation19 + 용도선택1 + GPIO30 + EXTI활성288/비활성18 + 콜백변경3 + ADC3이다.
- GPIO 1,500핀 설정, EXTI 활성 2,016핀 설정, 비활성 126핀 설정을 실제 화면에서 변경했다. 용도 선택 370항목은 전기적 실행 전수검사와 구분한다.
- 생성 HAL 실행 **342건**. 생성/실행 코드 684파일의 해시, 사례별 JSONL 342개, 저장 복구 파일 85개(실행 84개·라벨 검증 1개)의 해시를 재확인했다. 각 사례에서 시작 1회·상태 1회 이상·정지 1회와 단일 프로젝트 해시를 대조했다. 전체 시작 342건/상태 393건이며 상태 수에는 주기적 추가 기록이 포함된다.
- Renderer 오류·진단 기록 경고·실행 오류·회로 fault/경고 0건. 무효 입력을 의도적으로 거부한 console error 12건은 정상 검증 결과로 남겼다. 실행 중 진단 파일이 회전한 뒤에도 이전/현재 파일을 이어 읽어 증거를 보존했다.
- 시작·종료 및 최종 수집 시 소스 해시 `1b43991b345387c0105aac31e2b3e3eb6b11cddac11ee19b44fe1604f0363e32`가 동일했다. 범위는 Git 추적 `src/`, `desktop/`, `package.json`이다. 검사 스크립트 역시 실행 시작 이후 수정되지 않았음을 확인했다.
- 원본 1,113파일을 사용자 프로필 없이 ZIP으로 보존하고 내용별 SHA-256을 재검증했다. [최종 보고서](REPORT.md), [검증 집계](evidence/verification.json), [원본 증거](evidence/ui-runtime-evidence.zip), [체크섬](evidence/SHA256.txt)을 참조한다.
- 이전 0.24.0 JSON은 처음 기록한 SHA-256 그대로이며, 실패·중간 결과도 덮어쓰지 않았다. 이번 결과는 0.25.0 개발 소스 수정본 검사이고 공개 Release EXE 재검사·원격 CI·버전 상승·배포는 수행하지 않았다.
