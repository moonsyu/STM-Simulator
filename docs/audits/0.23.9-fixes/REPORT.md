## 증거와 범위

- 소스 검증: 365개 단위 검사, C 의미 14개와 변환 소스 2개 GCC 대조/ARM ABI 검사, 114장치·979 HAL 카드, 701단선 복구·114손상 회로 재실행, 128초기화·114재적용 통과. 핀 라벨 변경 후 재적용도 114종 모두 보존됩니다.
- 실제 Electron 저장/전환/터미널/종료 복원, 52화면의 22,684개 글자 대비 검사, 실제 GCC/GDB/clangd/ARM 도구, 포터블 EXE의 updater와 패키지 내부 업데이트 도우미 검사를 통과했습니다.
- 병렬 HAL 검사 중 L298N 13핀 항목 1건이 180초 시간 한도를 초과했습니다. 같은 소스를 단독 재검사해 108.6초에 10개 카드가 모두 통과했습니다. 첫 시도 실패와 재검사 기록을 구분해 보존했으며 다른 코드로 대체하지 않았습니다.
- `evidence/`: 재현 가능한 수정 후 요약. 큰 장치 원본 로그는 `work/test-results/fixes-0239/devices`에 보관합니다.
- 개별 단선은 전기적 연결·신호 분리 복구를 검사합니다. 전체 손상 회로는 복구 후 다시 실행합니다. HAL 카드는 해당 함수 도달·반환 상태를 판정하고 장치 전체 동작은 전체 예제로 따로 판정합니다.
- 사용자 구조체 정렬은 지원되는 스칼라/중첩 구조체 범위입니다. HAL 내부 구조체는 인터프리터의 값 모델이며 하드웨어 메모리 ABI가 아닙니다. 전체 C 표준, 물리 보드, 임의의 모든 입력 조합을 보증하지 않습니다.
- 저장 journal은 정상 파일 시스템 작업 실패와 프로세스 중단에서 복구합니다. 디스크 자체 고장까지 보장하지 않으며, 외부 편집 충돌은 사용자 파일을 덮어쓰지 않고 복구 기록을 보존합니다.
- 기존 v0.23.8 태그/배포 파일은 보존합니다. 해당 ZIP의 포터블 런처 누락과 메타데이터 출처 누락을 새 버전에서 해결합니다.

## 의존성 변경 근거

DOMPurify는 공식 [3.4.17 릴리스](https://github.com/cure53/DOMPurify/releases/tag/3.4.17)를 사용합니다. Monaco 0.57.0의 vendored 3.4.15는 번들 입력에서 제외하고 잠긴 npm 배포본으로 연결하며, 그래프 검사와 원본 라이선스 보존을 수행합니다. [IN_PLACE 권고](https://github.com/advisories/GHSA-6688-9rhm-gjv2)의 수정 버전 이상입니다.

빌드 의존성의 brace-expansion, fast-uri, http-cache-semantics를 수정 버전으로 갱신했습니다. sprintf-js 의존 경로는 [global-agent 4.1.3](https://github.com/gajus/global-agent/releases/tag/v4.1.3)으로 교체하고 Electron downloader의 bootstrap 및 실제 로컬 프록시 경유를 검사했습니다. 경고 제거를 앱에서 공격이 재현됐다는 의미로 해석하지 않습니다.
