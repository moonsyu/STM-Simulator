# 로컬 진단 파일

0.23.1부터 Windows 앱은 `%APPDATA%\STM32 Circuit Lab\diagnostics\`에 다음 파일을 기록합니다. 웹 개발 모드는 파일 기록 없이 실행됩니다.

- `events.jsonl`: 앱 시작, 화면 실행 로그, UART 데이터, Docs 적용 API·핀 배정·보완 내역, 오류, 시뮬레이션의 GPIO·부품 전류·점등 상태. 각 행은 JSON이며 실제 시각·앱 버전·세션 ID·최근 회로 SHA-256을 포함합니다.
- `events.previous.jsonl`: 이전 로그. 파일당 최대 약 1 MB이며 이전 파일 하나만 유지합니다.
- `latest-project.stm32lab`: 최근 자동 저장 회로. main.c, MCU 설정, 부품·다리 장착·배선·Docs 바인딩을 포함합니다. 앱 시작, 자동 저장, Docs 적용 성공/실패, 실행 시작, 업데이트 직전에 갱신합니다. 임시 파일에 쓴 뒤 교체합니다.

진단은 이 파일부터 확인합니다. 실행 상태는 2초 간격과 정지 직전에 기록하므로 모든 GPIO 에지를 보관하는 파형 파일은 아닙니다. 회로 사본은 가장 최근 상태 하나만 남습니다. 이벤트의 `projectSha256`과 사본의 해시가 다르면 이후 편집된 사본이므로 과거 코드 상태로 단정하면 안 됩니다.

사용자 코드와 UART 내용은 로컬에만 저장하며 서버나 GitHub로 전송하지 않습니다. 실제 사용자의 진단 사본은 저장소에 커밋하지 않습니다. 디스크 오류가 나더라도 회로 편집·시뮬레이션은 계속 동작합니다. 파일 크기·입력 크기·대기열을 제한하고 메인 창의 요청만 허용합니다.

재현 검사: `node scripts/docs-writepin-check.cjs`. 별도 임시 프로필의 숨긴 Electron 창에서 LED Docs 적용, SET/RESET, GND 누락 복원과 실제 파일 기록을 검사합니다. 현재 사용 중인 앱과 회로에는 접근하지 않습니다.

0.23.0 이하에는 화면 로그만 있습니다. 기존 문제 조사에는 앱 프로필의 Local Storage를 별도 폴더로 복사해 읽었으며 원본 데이터베이스는 변경하지 않았습니다.
